## Вердикт

Сейчас этап «предобработки» почти пустой: отбросили служебные колонки, проверили NaN/inf, затем сразу признаки и `RobustScaler`. В markdown прямо сказано, что данные «чистые — предобработка не нужна». Для сырых волн ФЭУ это **архитектурно неверно**: «чистые» ≠ «готовые к кластеризации».

Главный рычаг не в ещё одном scaler’е, а в **физической подготовке волны** (пьедестал → 3σ ROI → калибровка PSD → нормировка формы → QC). Текущий ноутбук этот слой фактически пропустил и сразу ушёл в кластеризацию на вырожденных агрегатах.

## 2. Приоритетный конвейер предобработки волны

### 2.1. Педьестал и шум (обязательно)

По Description: нулевая линия = среднее по **первым 50** отсчётам; шум = σ того же окна.

Сделать для каждой волны:

- `baseline`, `noise_std`;
- `x0 = x - baseline` (дальше все суммы/PSD только по `x0`);
- пересчитать SNR как `peak_above_baseline / noise_std`, а не `peak / baseline` (сейчас snr≈1.0005 — артефакт определения).

Без вычитания baseline long-gate почти константен, PSD «прилипает» к стене ~0.06 (~91% событий).

### 2.2. Выделение ROI сигнала (3σ), не вся запись 500

Description: сигнал = от пика до возврата к `baseline + 3σ`.

Сейчас в ноутбуке `charge = sum(все 500)` → в long попадает длинный шумовой хвост → PSD вырождается.

Предобработка:

- найти `i_max`, `i_end_3σ`;
- считать charge/PSD **только по ROI**;
- сохранить `roi_length`, флаг `no_3σ_hit` (не дошли до порога до конца записи).

Это как раз тот шаг, который в ноутбуке пропущен, хотя в `src/sygnal_clustering/signal_extraction.py` идея ROI уже ближе к методичке.

### 2.3. Калибровка окон PSD как часть prep, не «магии модели»

Зафиксировать сетку `(offset, short_len)` и критерий качества **гистограммы PSD** (глубина долины / разделение мод), не silhouette.

Также согласовать определение:

- ноутбук: `short/long`;
- Description: часто `(long−short)/long`.

Пока PSD не бимодален — в модели ранний вход запрещён (gate в пайплайне).

### 2.4. Нормировка формы (из‑за насыщения АЦП)

Peak ∈ [14827, 14838], σ≈1.46 → амплитуда почти бесполезна.

На prep:

- `x_norm = x0 / peak_above_baseline` (или / charge ROI);
- дальше decay/PSD/хвост на нормированной форме;
- сырой peak оставить только как QC-признак насыщения (`is_saturated`).

### 2.5. QC-флаги → будущий класс 2 (без квоты 5%)

На этапе prep разметить **кандидатов**, не финальные метки:

- pile-up / ≥2 локальных максимума;
- `decay_time` упирается в конец окна;
- ROI слишком короткий / слишком длинный;
- экстремальный baseline drift;
- PSD вне основного коридора после калибровки окон.

Доля класса 2 потом **emerges** из этих правил + overlap долин, а не из `top 5%` posterior.

### 2.6. Признаковый слой после prep (ещё не модель)

Минимальный набор после п.2.1–2.4:

- PSD (калиброванный), decay / τ (лучше эксп. fit, как в Description), charge ROI, tail ratio;
- **не** кормить кластеризацию сырыми peak/snr в текущем виде.

Отдельно: отбросить или сильно понизить вес признаков с near-zero variance (сейчас peak, snr, «стена» PSD).

### 2.7. Масштабирование — только после живых признаков

`RobustScaler` сейчас маскирует одномерие (PC1=100%). Оставить, но:

- fit только на полном наборе с фиксацией seed;
- не масштабировать бинарные QC-флаги;
- для GMM предпочтителен `QuantileTransformer` уже на **исправленном** PSD/decay.

## 3. Чего на prep делать не стоит

- Удалять «выбросы» ради красоты EDA — в этой задаче они часто и есть класс 2.
- Балансировать классы / квотировать 5% на этапе предобработки.
- Кластеризовать сырые 500 отсчётов без ROI и baseline (дорого и шумно).
- Считать «предобработка не нужна», потому что нет NaN.

---

## 4. Минимальный diff относительно текущего ноутбука

Вставить **явный блок § Preprocessing** между загрузкой и `extract_features`:

1. baseline / σ → вычитание;  
2. 3σ ROI → charge/PSD только по ROI;  
3. QC-флаги;  
4. отчёт: доля насыщения, доля «стена PSD», доля незакрытого 3σ, гистограмма PSD до/после калибровки окон.

**Критерий готовности prep:** PSD или decay-гистограмма показывает два пика с долиной. Пока этого нет — предобработка не закончена, модели рано сравнивать.

---

## 5. Одной фразой

На этапе предподготовки в текущем ноутбуке нужно не «ещё почистить таблицу», а **вернуть физическую обработку импульса** из Description; без baseline/ROI/калибровки PSD дальнейшие модели сравнивают артефакты, а не типы частиц.
