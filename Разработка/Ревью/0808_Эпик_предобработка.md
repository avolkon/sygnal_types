## Проблема (as-is), подтверждено по коду ноутбука

Сейчас prep фактически = drop служебных колонок + NaN/inf check → сразу агрегаты и `RobustScaler`.

Код `extract_features` (§4) фактически делает:

```python
baseline = x[:, :50].mean(axis=1)     # считается, но НЕ вычитается из x
charge   = x.sum(axis=1)              # sum(500), без ROI
short    = x[i, p+3 : p+3+30].sum()   # окно от argmax
psd      = short / (charge + 1e-9)    # short/long, не (long-short)/long
snr      = peak / (baseline + 1e-9)   # ≈ 1.0005
```

Следствия:

- нет вычитания пьедестала → PSD «стена» ~0.06 (~91% событий);
- `charge = sum(500)` без 3σ ROI → long-gate зашумлён;
- `snr ≈ 1.0005` — **диагностический сигнал**: пик почти равен пьедесталу у всех волн (не только «плохая формула»);
- заголовок §4 обещает «3σ», код ROI не делает;
- peak насыщен (σ≈1.46) и всё равно идёт в кластеризацию;
- класс 2 нечем наполнять физически → инженерная квота 5% (модель 5, §7–§9);
- диапазон датасета **0…14838** при `peak ≈ baseline` у всех волн → **рабочая гипотеза с высокой уверенностью**: отрицательный импульс ФЭУ на высоком пьедестале; `argmax` ловит пьедестал, сигнал — провал вниз. Без коррекции полярности `x - baseline` даёт `max ≈ 0`, и ROI/PSD снова вырождаются.

**Инвариант эпика:** «нет NaN» ≠ «готово к кластеризации».

**Инвариант `src/`:** текущий `signal_extraction.py` режет окно по **40% decay**, не вычитает пьедестал и повторяет SNR-артефакт — **не** считать его готовой реализацией Description / 3σ.

## Ценность (to-be)

1. Признаки отражают **форму высвечивания на правильной полярности**, а не АЦП-артефакты.
2. Измеримый gate: **модели не сравниваем**, пока PSD/decay не бимодальны — по `valley_ratio`, не «на глаз».
3. Класс 2 готовится как **emergent residual** (QC + overlap), не как `top 5%` posterior.
4. Три окна (ROI 3σ, decay-40%, PSD short/offset) — отдельные контракты.
5. Единая физика extraction в `src/`; ноутбук только вызывает.
6. Legacy §5–§9 явно помечены как pre-prep.

## Три контракта (не смешивать)

| Контракт | Определение | Назначение |
|---|---|---|
| **ROI / long gate** | `[i_peak … i(μ + N_SIGMA·σ)]` на `x0` | charge, long для PSD |
| **decay 40%** | от пика до уровня `(1 − DECAY_FRAC) · peak_above` на `x0`/`x_norm` | `decay_time` |
| **PSD short gate** | окно `(PSD_OFFSET, PSD_SHORT)` внутри ROI | дискриминатор формы |

Запрещено склеивать decay-окно с 3σ-ROI (как сейчас в `signal_extraction.py`).

## Целевая архитектура в ноутбуке

```text
§2 Load (X raw)
§3 EDA raw (оставить; уже есть row_max/argmax — добавить row_min/argmin)
§ Preprocessing
      raw → POLARITY → x_pos → baseline/noise → x0 → ROI → QC
      gate: valley_ratio(PSD|decay) < VALLEY_RATIO_MAX
§4 Feature contract      ← бывший extract_features, только на prep
§5+ Scaling / models     ← legacy до EPIC-FE; banner; не тюнить LB
```

Константы — **одна ячейка** в начале § Preprocessing:

`POLARITY`, `BASELINE_BINS`, `N_SIGMA`, `DECAY_FRAC`, `PSD_FORMULA`, `PSD_OFFSET`, `PSD_SHORT`, `VALLEY_RATIO_MAX`, `RANDOM_STATE`.

- Default PSD (Description): **`(long − short) / long`**. `short/long` — только A/B.
- Default gate: **`VALLEY_RATIO_MAX = 0.7`** (калибруемая константа).
- Default decay: **`DECAY_FRAC = 0.40`** → порог на `x0`: `thr = (1 - DECAY_FRAC) * peak_above_baseline`.

Pipeline ориентации (явно):

```text
raw → (если negative: отразить относительно пьедестала) → x_pos
    → baseline/noise на окне пьедестала → x0 = x_pos - baseline
    → ROI / PSD / decay только на x0 (decay также на x_norm после US-4)
```

## User stories (реализация)

### US-0. Spike полярности (блокер перед US-1)
**Как** архитектор пайплайна, **хочу** до ROI проверить полярность импульса, **чтобы** не строить 3σ/PSD на неверной оси.

**Acceptance**
- [ ] На агрегатах §3 добавить `row_min` / `argmin` рядом с `row_max` / `argmax`
- [ ] На 20–50 волнах визуально сравнить форму вокруг `argmax` и `argmin` (`plt.plot`)
- [ ] Зафиксировать `POLARITY ∈ {"negative","positive"}` + 1 абзац обоснования
- [ ] Ввести `x_pos` — единственный вход для US-1…US-8

**Оценка:** XS (первая ячейка prep; визуал обязателен)  
**Зависит от:** —  
**Блокирует:** US-1…US-8

### US-1. Педьестал и шум
**Как** аналитик сигналов, **хочу** вычитать нулевую линию и оценивать шум по первым 50 отсчётам на `x_pos`, **чтобы** суммы и PSD не смешивались с пьедесталом.

**Acceptance**
- [ ] Pipeline: `raw → x_pos → baseline/noise → x0` (см. схему выше)
- [ ] `baseline`, `noise_std` по окну пьедестала (`BASELINE_BINS=50`)
- [ ] `x0` — единственный вход для charge/PSD/ROI; decay — на `x0`/`x_norm`
- [ ] `SNR = max(x0) / (noise_std + eps)`; старый `peak/baseline` убран из отчётных метрик
- [ ] В выводе: распределения baseline / noise_std / peak_above; сравнение нового SNR со старым

**Оценка:** S  
**Зависит от:** US-0

### US-2. ROI по правилу 3σ
**Как** физик обработки импульса, **хочу** обрезать сигнал от пика до `μ + N_SIGMA·σ` на `x0`, **чтобы** long-gate не включал шумовой хвост.

**Acceptance**
- [ ] `i_peak`, `i_end_3σ` на `x0`
- [ ] `charge`, short/long только на ROI
- [ ] ROI **≠** окно decay 40% (отдельные поля/функции)
- [ ] `roi_length`, `no_3σ_hit`; отчёт долей и распределения длины ROI
- [ ] `signal_extraction.py` **переписывается** (не эталон); ноутбук вызывает `src`

**Оценка:** M  
**Зависит от:** US-1

### US-3. Калибровка окон PSD (prep-gate)
**Как** ML-аналитик, **хочу** подобрать `(psd_offset, psd_short)` при зафиксированной формуле PSD, **чтобы** не кормить модели вырожденным признаком.

**Acceptance**
- [ ] Default: `psd = (long − short) / long`; `short/long` — только A/B, не в `X_clust` по умолчанию
- [ ] Сетка `(offset, short_len)` + критерий `valley_ratio` (D4'); не silhouette
- [ ] Три контракта ROI / decay / PSD-окон не переиспользуют друг друга без обоснования
- [ ] Edge-cases: мод < 2 → gate FAIL; мод > 2 → две доминирующие / задокументировать; параллельно `valley_ratio` на decay
- [ ] Артефакты: гистограммы до/после, константы, значение `valley_ratio`
- [ ] **Gate:** если `valley_ratio ≥ VALLEY_RATIO_MAX` — markdown STOP к моделям; FE для диагностики всё равно

**Оценка:** L (critical path)  
**Зависит от:** US-2

### US-4. Нормировка формы при насыщении АЦП
**Как** аналитик, **хочу** работать с нормированной формой на верной оси, **чтобы** убрать почти константный peak из кластеризации.

**Acceptance**
- [ ] Default: `x_norm = x0 / peak_above_baseline` (не / charge ROI; второй вариант — только опциональный флаг)
- [ ] `decay_time` на `x0`/`x_norm` с порогом `thr = (1 - DECAY_FRAC) * peak_above_baseline` (смысл Description: спад на 40% → уровень 60% амплитуды над нулём `x0`; **не** на сыром `x`)
- [ ] `is_saturated` как QC-флаг
- [ ] `peak` и старый `snr` не в `X_clust` по умолчанию

**Оценка:** S  
**Зависит от:** US-1, US-2

### US-5. QC-флаги кандидатов в класс 2
**Как** архитектор пайплайна, **хочу** на prep помечать патологические/неоднозначные импульсы, **чтобы** класс 2 строился из физики, а не из квоты 5%.

**Acceptance**
- [ ] Флаги минимум: multi-peak/pile-up; decay упирается в конец окна; ROI short/long outliers; baseline drift; PSD вне коридора после калибровки
- [ ] Prep **не** пишет `cluster`; только `qc_*` / `candidate_class2`
- [ ] Сводка долей; запрет «5% по ТЗ» в блоке prep
- [ ] Модель 5 / квоту uncertain не трогаем (только disclaimer US-8)
- [ ] Документировано: доля класса 2 emergent на EPIC-Class2

**Оценка:** M  
**Зависит от:** US-2, US-3

### US-6. Признаковый слой после prep
**Как** ML-инженер, **хочу** стабильный набор признаков после prep, **чтобы** FE и модели стартовали с одного контракта.

**Acceptance**
- [ ] Default: `psd_calibrated`, `decay_time` (US-4), `charge_roi`, `tail_ratio`
- [ ] Near-zero variance отфильтрованы или понижены в весе (отчёт)
- [ ] `feat_df.describe()` + вывод «что кормим моделям»
- [ ] Опционально: эксп. fit τ — флаг, не блокер DoD

**Оценка:** M  
**Зависит от:** US-3, US-4

### US-7. Масштабирование после живых признаков
**Как** ML-аналитик, **хочу** scaler только на непрерывных «живых» признаках, **чтобы** не маскировать одномерие мёртвых входов.

**Acceptance**
- [ ] `RobustScaler` и/или `QuantileTransformer` после US-6, с `RANDOM_STATE`
- [ ] Бинарные QC не масштабируются
- [ ] PCA/EVR: если PC1≈100% — риск в выводе (не блокер при живой PSD)

**Оценка:** S  
**Зависит от:** US-6

### US-8. Интеграция в ноутбук, воспроизводимость и legacy-баннер
**Как** студент/проверяющий, **хочу** явный § Preprocessing и границу с legacy, **чтобы** ТЗ и Run All не противоречили друг другу.

**Acceptance**
- [ ] § Preprocessing между EDA raw и FE (рефактор extract под prep)
- [ ] Markdown-выводы после этапа
- [ ] Все константы prep в одной ячейке; без интерактивного upload
- [ ] Баннер перед §5: «ниже — модели на pre-prep признаках, квота 5% условна; результат prep выше не отменяет эту секцию; актуализация моделей — EPIC-FE»
