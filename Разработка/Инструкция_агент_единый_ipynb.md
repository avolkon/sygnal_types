# Инструкция для агента: создание единого ipynb для Kaggle-соревнования

Универсальный playbook для перевода многофайлового ML-репозитория в **один самодостаточный ноутбук** для сдачи (учебный проект / сессия).  
Эталон реализации: `notebooks/avo_sygnal_types_2.ipynb` в репозитории `sygnal_types`.

---

## 0. Входные данные для агента

Перед началом собери:

1. **Ссылку на Kaggle-соревнование** — формат submission, метрика, описание классов.
2. **ТЗ / методичку** — обязательные разделы (EDA, модели, выводы).
3. **Пример оформления** (если есть) — стиль выводов, структура §.
4. **Существующий код** — `src/`, `scripts/`, старые ноутбуки, лучший submission.
5. **ФИО и группу студента** — для титульной ячейки.
6. **Имя итогового файла** — например `notebooks/avo_<topic>_2.ipynb`.

**Ограничение:** итоговый `.ipynb` должен выполняться **Run All** без установки пакета из `src/` (код инлайн), если иное не оговорено.

---

## 1. Общий алгоритм работы агента

```
┌─────────────────────────────────────────────────────────────┐
│ 1. Разведка репозитория (src, scripts, notebooks, data)    │
│ 2. Выделить лучший пайплайн и 3–5 моделей для сравнения    │
│ 3. Спроектировать оглавление § ноутбука                     │
│ 4. Создать scripts/build_<name>.py + notebook_conclusions.py│
│ 5. Перенести рабочий код в code-ячейки (инлайн)            │
│ 6. После каждого § — markdown-вывод (студент + консилиум)  │
│ 7. Run All → сверить цифры в выводах с output ячеек       │
│ 8. submission.csv + скриншот Kaggle                        │
└─────────────────────────────────────────────────────────────┘
```

**Не делать:**
- не раздувать ноутбук импортами из половины `src/`;
- не оставлять выводы только в `print()` — нужны **markdown-ячейки**;
- не выбирать финал только по одной метрике, если ТЗ задаёт структуру классов.

## 3. Правила оформления code-ячеек

Каждая code-ячейка:

```python
# @title §N. Краткое название
"""Однострочное описание блока."""
# --- подсекция ---
...
```

- **`# @title`** на **каждой** code-ячейке (требование платформы / Colab).
- **Docstring** в первой строке после title.
- **Блочные комментарии** `# --- ... ---` между логическими шагами.
- **`RANDOM_STATE = 42`** — в §1, использовать везде.
- **Без** ссылок на «матчасть», «лекцию» — формулировки естественные.

---

## 4. Правила оформления markdown-выводов

### Шаблон одного вывода (обязательный)

```markdown
## 📊 Выводы: <название блока> (§N)

| Колонка 1 | Колонка 2 | … |
|-----------|-----------|---|
| …         | …         |   |

**Интерпретация:**

- пункт 1 с цифрами из ячейки выше;
- пункт 2 — физический / предметный смысл;
- пункт 3 — следствие для модели.

**На графике / в таблице:** что видно глазами (облако, перекрытие, перекос классов).

**Вывод:** одно предложение — главная мысль блока.

**✅ Следующий шаг:** что делаем дальше.
```

### Голос текста

- от **лица студента** («я увидела», «зафиксировала»);
- упоминание **консилиума** (аналитик, физик, ML-инженер) — 1 раз в начале или в итоге;
- язык **простой**, без избыточного жаргона;
- **цифры** — из output ячеек (`describe()`, `compare_df`, `evr`), не «на глаз».

### Где хранить тексты

```
scripts/notebook_conclusions.py   # AFTER_LOAD, AFTER_EDA, … FINAL
scripts/build_<name>.py           # md(_conc["AFTER_LOAD"]), …
```

Пересборка ноутбука после правки выводов:
```bash
python scripts/build_<name>.py
```

## 5. Выбор финальной модели (чеклист для агента)

1. Запустить **Run All**, получить `compare_df`.
2. Сравнить **≥3 модели** по:
   - внутренним метрикам (silhouette, CH, DB — для кластеризации);
   - **долям классов** / бизнес-ограничениям ТЗ;
   - устойчивости (`random_state` фиксирован).
3. Явно записать в выводе: **«лучшая метрика ≠ финал»**, если так.
4. Подобрать 1 гиперпараметр финала (grid 3 значений).
5. Сохранить `submission.csv` в формате Kaggle.
6. Загрузить на Kaggle, вставить скриншот в последнюю md-ячейку.

## 6. Генератор ноутбука (скелет `build_*.py`)

```python
#!/usr/bin/env python
"""Generate notebooks/<name>.ipynb."""

import json
from pathlib import Path

ROOT = Path(__file__).resolve().parents[1]
OUT = ROOT / "notebooks" / "<name>.ipynb"

_conc: dict = {}
exec((ROOT / "scripts" / "notebook_conclusions.py").read_text(encoding="utf-8"), _conc)

def md(text: str) -> dict:
    return {"cell_type": "markdown", "metadata": {},
            "source": text.splitlines(keepends=True)}

def code(text: str) -> dict:
    return {"cell_type": "code", "execution_count": None, "metadata": {},
            "outputs": [], "source": text.splitlines(keepends=True)}

CELLS = [
    md("""# Титул"""),
    code("""# @title §1. Импорты\n..."""),
    code("""# @title §2. Загрузка\n..."""),
    md(_conc["AFTER_LOAD"]),
    # …
]

def main():
    OUT.parent.mkdir(parents=True, exist_ok=True)
    nb = {"nbformat": 4, "nbformat_minor": 5,
          "metadata": {"kernelspec": {"display_name": "Python 3",
                                      "language": "python", "name": "python3"}},
          "cells": CELLS}
    OUT.write_text(json.dumps(nb, ensure_ascii=False, indent=1), encoding="utf-8")

if __name__ == "__main__":
    main()
```

## 7. Адаптация под другое Kaggle-соревнование

| Аспект | sygnal_types (эталон) | Другой репозиторий |
|--------|----------------------|-------------------|
| Тип задачи | кластеризация (3 класса) | классификация / регрессия / NLP / CV |
| §4 признаки | PSD, charge, decay | TF-IDF, embeddings, аугментации |
| §5–6 | PCA, ICA | feature selection, target encoding |
| §7 модели | KMeans, GMM×3 | LR, XGB, CatBoost, ансамбль |
| §8 tune | `uncertain_fraction` | learning_rate, depth, threshold |

| Метрика | accuracy (кластеры) | AUC, RMSE, F1 — смотреть leaderboard |

## 8. Проверка перед сдачей (чеклист агента)

- [ ] Run All без ошибок (локально и/или Colab)
- [ ] Датасет находится по `data/` + fallback-путям
- [ ] Каждая code-ячейка имеет `# @title` и docstring
- [ ] После каждого § — md-вывод в едином стиле
- [ ] Цифры в выводах совпадают с output ячеек
- [ ] ≥3 модели в `compare_df`
- [ ] `submission.csv` проходит assert (размер, колонки, допустимые значения)
- [ ] Скриншот Kaggle вставлен (или placeholder с инструкцией)
- [ ] `python scripts/build_<name>.py` воспроизводит тот же ipynb
- [ ] Production-код в `src/` не сломан (pytest при наличии)
