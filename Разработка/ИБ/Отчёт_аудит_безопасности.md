# Отчёт по безопасности кодовой базы `sygnal_types`

**Дата:** 2026-05-23  
**Роль:** архитектор с опытом в ИБ / white-box аудит  
**Контекст:** офлайн ML-проект (Kaggle, Jupyter, CLI-скрипты). Нет веб-сервера, API, БД, аутентификации. Поверхность атаки — локальный запуск кода и доверие к файлам в репозитории.

**Общая оценка:** для учебного/offline-проекта риск **низкий–умеренный**. Критических уязвимостей «из коробки» нет. Основные проблемы — десериализация `joblib`, произвольное чтение файлов и практики supply chain.

> Рекомендации зафиксированы для последующей работы; **исправления не внедрялись** на момент сохранения отчёта.

## Найденные риски (по приоритету)

### 1. Высокий — небезопасная десериализация `joblib.load` (RCE)

**Где:** `src/sygnal_clustering/pipeline.py`, `src/sygnal_clustering/pipeline_v2.py`

```python
@classmethod
def load(cls, path: Path | None = None) -> SygnalClusteringPipeline:
    path = path or ARTIFACTS_DIR / "pipeline.joblib"
    return joblib.load(path)
```

**Суть:** `joblib` использует pickle. Загрузка чужого `.joblib` = **выполнение произвольного кода**.

**Факт:** в git лежит `artifacts/pipeline.joblib` (~7.7 MB).

**Когда опасно:** если кто-то подменит артефакт или вы загрузите модель из недоверенного источника.

**Рекомендации (не внедрены):**

- не коммитить `.joblib` в git; хранить checksums / releases;
- загружать только из доверенных путей;
- для обмена моделями — ONNX или `skops` с ограниченными типами вместо pickle.

### 2. Средний — произвольное чтение файлов через `load_waveforms(path)`

**Где:** `src/sygnal_clustering/data.py`

```python
def load_waveforms(path: Path | str | None = None) -> np.ndarray:
    path = Path(path) if path is not None else resolve_data_path()
    df = pd.read_csv(path, sep=" ", header=None, skipinitialspace=True)
```

**Суть:** параметр `path` не ограничен каталогом проекта.

**Смягчающие факторы:** проверка формы `(23479, 500)` и `isfinite` — защита от «мусорных» данных, не от чтения.

**Рекомендации (не внедрены):** ограничить путь каталогом `REPO_ROOT` (`is_relative_to`).

---

### 3. Средний — supply chain: незакреплённые зависимости

**Где:** `requirements.txt`, `pyproject.toml`

```
numpy>=1.24
pandas>=2.0
scikit-learn>=1.3
...
```

**Суть:** при `pip install -r requirements.txt` каждый раз могут подтянуться новые версии с новыми CVE.

**Рекомендации (не внедрены):**

- lock-файл (`pip freeze`, Poetry, uv);
- периодически `pip-audit` / Dependabot;
- проверка уязвимостей в CI.

---

### 4. Средний — подмена модулей через `sys.path.insert(0, ...)`

**Где:** ноутбуки и скрипты в `scripts/`

```python
ROOT = Path.cwd()
sys.path.insert(0, str(ROOT / "src"))
```

**Суть:** при запуске из «чужой» директории возможен импорт подделанного пакета `sygnal_clustering`.

**Рекомендации (не внедрены):**

- `pip install -e .`;
- в ноутбуках использовать фиксированный `REPO_ROOT`, а не `cwd()`.

### 5. Низкий — запись файлов в корень репозитория

**Где:**

- `pipeline_v2.py`: `SUBMISSION2_PATH = REPO_ROOT / "submission2.csv"`
- `tune_method_c.py`: `SUBMISSION4_PATH = ROOT / "submission4.csv"`

**Суть:** операционный риск — засорение корня, случайный коммит артефактов.

**Рекомендация (не внедрена):** все сабмиты только в `Разработка/Эксперименты/`.

---

### 6. Низкий — DoS через большие файлы

**Где:** `pd.read_csv(path)` без лимита размера.

**Суть:** подставной многогигабайтный файл → исчерпание RAM.

**Рекомендация (не внедрена):** проверять `path.stat().st_size` до загрузки.

---

### 7. Низкий — шаблон загрузки из интернета в документации

**Где:** `Разработка/Подготовка/ТЗ2.txt`

```python
url = f"https://drive.usercontent.google.com/download?id={file_id}..."
response = requests.get(url, timeout=60)
with open("taxi.csv", "wb") as f:
```

**Суть:** при переносе в Colab без доработок — нет проверки размера/хэша; SSL у `requests` включён по умолчанию.

**Рекомендация (не внедрена):** Kaggle API + проверка хэша файла после скачивания.

**Рекомендация (не внедрена):** не запускать чужие ноутбуки вслепую; для сдачи — экспорт логики в `.py` + pytest.

## Что в порядке (хорошие практики)

- **Нет секретов** в коде (по текущему состоянию).
- **Нет** `eval`, `exec`, shell-команд.
- **Валидация данных** после загрузки: размерность, `isfinite`.
- **Фиксированный `RANDOM_STATE`** — воспроизводимость.
- **`.gitignore`** для venv, cache; нет `.env` в репо.
- **Нет attack surface** в сети — проект не деплоится как сервис.

## Матрица: что реально может случиться

| Сценарий | Вероятность | Ущерб |
|----------|-------------|-------|
| Загрузка подменённого `pipeline.joblib` | Низкая (если только свой git) | **Критический** (RCE) |
| Запуск ноутбука от третьего лица | Низкая | Высокий |
| CVE в новой версии sklearn/pandas | Средняя (без lock) | Средний |
| Чтение чужого файла через `path=` | Низкая (нет UI) | Средний |
| Утечка Kaggle API key | **Не обнаружена** | — |

## План исправлений (отложен)

1. Убрать `*.joblib` из git, добавить в `.gitignore`; документировать «не загружать joblib из недоверенных источников».
2. Ограничить `load_waveforms` путями внутри `REPO_ROOT`; перенести `SUBMISSION2_PATH` / `submission4` в `Разработка/Эксперименты/`.
3. Lock-файл зависимостей + `pip-audit` в CI.
4. Для Colab: безопасный блок загрузки (Kaggle API, проверка размера/хэша).
5. Опционально: `pip install -e .` вместо `sys.path.insert` в ноутбуках.

---

## Итог

Это **исследовательский offline-проект**, не production-система. Прямых дыр типа «SQL injection в API» нет. Главный реальный риск для разработчика — **pickle/joblib** и **недоверенные ноутбуки/зависимости**. Для Kaggle-сдачи текущий код **приемлем**, если не загружать чужие артефакты и не публиковать API-ключи Kaggle в ноутбуках.
