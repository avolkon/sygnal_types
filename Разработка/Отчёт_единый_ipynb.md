## 1. Исходное состояние

До рефакторинга под сессионную сдачу репозиторий представлял **многослойный ML-проект**:

| Компонент | Содержание |
|-----------|------------|
| `src/sygnal_clustering/` | production-пайплайн v3, legacy v1/v2, извлечение признаков, метрики |
| `scripts/` | `run_experiments.py`, генераторы ноутбуков 5/6, tune, legacy-скрипты |
| `notebooks/` (частично) | разрозненные ноутбуки опыта и инференса |

| `Разработка/` | ТЗ, планы, архив submission, пример ДЗ1 |

**Проблема для сдачи:** критерии 1–3 (EDA, кластеризация, код) требуют **одного самодостаточного ноутбука**, а не навигации по пакету, нескольким ipynb и CLI-скриптам.

## 2. Цель работы

Собрать **один воспроизводимый `.ipynb`**, в котором:

1. Загружается датасет (локально / Colab / платформа).
2. Проводится EDA с графиками.
3. После **каждого логического блока** — markdown-вывод от лица студента (с опорой на консилиум).
4. Сравниваются **не менее 3–5 моделей** кластеризации.
5. Выполняется подбор гиперпараметров финальной модели.
6. Генерируется `submission.csv` для Kaggle.
7. Вставляется скриншот лидерборда.

При этом **production-код в `src/` сохранён** для разработки и тестов; ноутбук — автономная «витрина» для проверяющего.

## 3. Что было сделано

### 3.1. Архитектура «генератор + выводы»

Вместо ручного копирования ячеек создан паттерн:

```
scripts/build_<имя>.py     →  собирает .ipynb из списка CELLS
scripts/notebook_conclusions.py  →  тексты markdown-выводов (AFTER_LOAD, AFTER_EDA, …)
```

**Преимущества:**
- выводы редактируются в одном `.py`-файле, без правки JSON ноутбука;
- структура ячеек версионируется в git;
- пересборка: `python scripts/build_avo_sygnal_types_2.py`.

### 3.3. Пять моделей кластеризации

| № | Модель | Роль в сравнении |
|---|--------|------------------|
| 1 | KMeans на (peak, charge, psd) | baseline |
| 2 | GMM-3 + QuantileTransformer | лучший silhouette, но завышен класс 2 |
| 3 | PCA + KMeans | снижение корреляции признаков |
| 4 | ICA + KMeans | негативный эксперимент (коллапс класса 2) |
| 5 | GMM-2 + 5% uncertain → класс 2 | **финал** по структуре ТЗ |

Критерий выбора финала: не только silhouette, но и **доли кластеров 0/1/2** (~52/43/5%).

### 3.4. Стиль выводов (эволюция)

1. **v1:** code-ячейки с `display(Markdown(f'''...'))` и f-строками из переменных.
2. **v2:** отдельные markdown-ячейки, стиль примера ДЗ1 (📊, таблицы, ✅).
3. **v3 (финал):** простой язык + таблица → **Интерпретация** → наблюдение на графике → **Вывод** → **✅ Следующий шаг**; цифры из `describe()` / `compare_df` после Run All.

### 3.5. Исправления по ходу работы

| Проблема | Решение |
|----------|---------|
| Scatter PSD vs charge: 2–3 точки | Ошибка в `extract_single`: обрезка сигнала по 3σ с пика → 1–3 отсчёта. Исправлено: long gate = импульс от пика до спада 40%, short gate = 30 отсчётов после пика+3 |
| Горизонтальная «стена» PSD ≈ 0.06 | `charge` считался по всей волне (500 отсчётов). Исправлено: charge только по выделенному импульсу |
| Выводы слишком «профессиональные» | Переписаны простым языком с привязкой к числам из ячеек |
| Разрозненные `artifacts/`, `artifacts_v2/`, `artifacts_v3/` | Объединены в `artifacts/v1`, `v2`, `v3` |
| Ноутбуки в корне | Все в `notebooks/` |
| Датасет в корне | Перенесён в `data/` |
